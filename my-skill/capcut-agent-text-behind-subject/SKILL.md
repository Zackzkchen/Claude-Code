# Text Behind Subject Edit

## 职责与完成标准

这是首轮成片 Skill，不是“把文字丢到画面上”的贴字。成片必须有正确的三层结构（底层原片、中间层文字、顶层抠像主体）、真实发生的遮挡关系、干净的主体边缘，以及一段文字完整可读的呈现窗口。优先让观众先读到文字、再看到人物从文字前走过；不要为了炫技把文字全程压在主体身上或让遮挡完全看不出来。

用户在已有 draft 上明确说“换文案/改字体、全片换某类转场、给某段慢放、加某个滤镜/贴纸/BGM”等时，不触发本 Skill，而交给对应原子包装 Skill 做精确修改。

## 固定多 Tool 工作流

严格按以下阶段执行。任何阶段未在**最新 draft** 中验收通过，都不能进入下一阶段；不把一次失败调用当作已完成。

| 阶段 | 先决输入与工具能力 | 必须产物 | 执行门禁 |
|---|---|---|---|
| 0. 开工检查 | 读取 Editing Track Context、最新 draft 和本轮可用 Tool schema | `capability_map`：素材理解、多视频轨与片段复制、抠像/蒙版、短文字、关键帧、动画、阴影/模糊类效果、回读能力 | 不臆造 Tool、抠像方式或参数；缺失能力从方案中删除，不用其它能力冒充，尤其不得用普通形状蒙版冒充人像抠像并声称已抠像。 |
| 1. Pass A：素材理解 | `draft_material_understanding(mode=event)` 或等价能力 | `subject_map`：主体位置与轮廓、行进方向、进出画时间、可用遮挡机会、背景干净区、边缘风险片段 | 只依据真实素材选片，先删除主体不清、与背景同色、剧烈运动模糊或主体贴边的片段；此遍不得为尚未入选的片段定最终文字坐标。 |
| 2. 分层搭建 | 当前可用的多轨创建、片段复制、裁剪与轨道排序能力 | `layer_stack`：底层原片 → 文字层位 → 顶层主体层，且上下两份同素材帧对齐 | 回读 draft，确认顶层与底层是同素材、同时间范围、同速度；未对齐时先修分层，禁止先加文字或效果。 |
| 3. Pass B：抠像与遮挡时序 | 顶层片段的人像抠像/蒙版能力 + 对最新 draft 的再次理解 | `matte_plan`、`occlusion_map`、`text_window` | 抠像必须先真实落在顶层片段上；只基于抠像后的真实主体位置计算遮挡窗口和覆盖比例，不凭想象设定数值。 |
| 4. 文字与融合规划 | `occlusion_map` + `text_window` + 最新 draft + 实际检索到的资源 | `text_plan` 与 `blend_plan` | 每处处理必须有具体 segment/时间窗、目的、资源候选和“不处理”的备选；文字必须保留完整可读窗口，融合手段以不损可读性为前提。 |
| 5. 分步执行 | 仅发现并使用本轮 schema 中真实存在的能力 | 已落入 draft 的分层、真实抠像、位于中间层的文字与必要融合 | 严格按“基线画面 → 分层/抠像 → 文字入中间层 → 可选融合与关键帧 → 定点微调”执行；每个窗口独立调用、独立回读。 |
| 6. 成片验收 | 最新 draft + 分层/遮挡/文字计划 | 验收结论与至多一轮定向修复 | 逐项确认层序正确、遮挡真实发生、主体边缘干净、文字可读；只修复失败项，禁止再开一轮自由包装。 |

## 客户端计划协同与走完率

内部阶段不是客户端任务单。首次调用 `UpdateEditingPlan` 时，只创建并持续维护以下五个 checkpoint；不要把检索、回读、重试或每一次抠像边缘修补拆成额外客户端步骤：

```text
1. Analyze subject and background
2. Stack duplicated layers and cut out subject
3. Place text behind subject
4. Blend text with scene motion
5. Verify occlusion and final QA
```

- 每个 checkpoint 只有在对应 draft 验收通过后，才调用 `UpdateEditingPlan` 标记完成并推进到下一项。不要只完成 Tool 调用就打勾，也不要等到所有工作结束才一次性推进。
- 一个 checkpoint 内优先使用当前 schema 支持的批量能力：分层复制、轨道排序、多条文字属性更新可合并为一次调用后统一回读；抠像与遮挡窗口因需独立验收可逐个执行，但不得为同一资源反复检索或为同一失败无限重试。
- 能力或资源缺失时必须完成**有边界的降级**，而不是停住整个 workflow：无人像抠像能力则用可关键帧的蒙版沿主体路径近似遮挡并记录 `matte_degraded`；蒙版也不可用则记录 `occlusion_unavailable`，把文字改为与主体不交叠的干净布局仍交付成片；无关键帧能力则改选静止镜头片段并记录 `blend_degraded`。只要基础成片仍可交付，该 checkpoint 应验收为完成并推进。
- 对同一目标 Tool 调用最多重试一次；重试前必须检查上次错误与最新 draft。不要在没有新信息时重复素材理解、重复检索或重复执行已成功的编辑。
- 在调用 `TaskFinished` 前，读取当前 `Editing Plan`：五个 checkpoint 均为成功才可完成任务。若当前 checkpoint 未完成，继续该 checkpoint 或调用 `UpdateEditingPlan` 推进；只有核心成片无法完成且无安全降级时才使用 `TaskNotExecuted`，并说明阻塞原因——本 Skill 的核心是“文字 + 正确层序”，短文字能力或多轨能力完全缺失即属于无安全降级。

## Two-Pass 素材理解与遮挡时序

只做两次主要理解，分别解决“用哪段主体”和“文字何时被挡”：不要每调一次文字位置或补一次边缘就重新全量分析。

1. **Pass A（checkpoint 1）**：从原始素材形成 `subject_map`，记录每个候选片段的主体大小、轮廓清晰度、行进方向、进出画时间、与背景的明暗/色彩差、可用时长和边缘风险（发丝、手持物、快速运动模糊、主体与画面边缘粘连）。此遍决定选片，不决定最终文字坐标与遮挡数值。
2. **分层（checkpoint 2）**：先把三层结构落到 draft。底层保留完整原片且不做任何抠像，顶层是同素材同时间范围的复制片段；宁可换片段，也不能用不对齐的两份素材硬凑遮挡。
3. **Pass B（checkpoint 3）**：抠像真实生效后，对最新 draft 再做一次理解，得到 `occlusion_map`。只对仍保留在时间线上的片段计算主体位置、候选文字区与覆盖比例；再据此生成 `text_window`：`reveal`（文字完整可读）→ `cross`（主体穿过文字前方）→ `hold|exit`（文字退出方式明确）。
4. `text_window` 至少要有一段约 0.6–1s 的完整可读期；`cross` 期的峰值覆盖应明显可见但不至于全遮，通常落在三成到七成之间，具体按主体大小和文案长度决定。
5. 无法获得逐帧主体位置时，只按可确认的进出画方向与大致路径做**区间级**判断，不虚构逐帧包围盒。必要时优先换片段、移动文字位置或缩短文字时长，不能为了制造遮挡把文字塞到主体面部或画面边缘之外。
6. `text_plan` 与 `blend_plan` 只能使用 Pass B 的 `occlusion_map` 与 `text_window`；已在 Pass A 被淘汰的片段不得成为文字或融合依据。

## 计划格式与调用规则

先在上下文中生成，不必展示给用户：

```text
layer_stack[]: track / role(background|text|subject_foreground) /
               source_material / time_range / speed / alignment_check
matte_plan[]: subject_segment / method(auto_cutout|mask|chroma) /
              retrieved_resource / fix_windows / fallback
occlusion_map[]: time_window / subject_position / text_zone /
                 coverage_ratio / edge_risk
text_window[]: reveal_start / cross_start / cross_end / hold_end / rationale
text_plan[]: segment / start-end / short_copy / anchor_zone / scale /
             font_style / z_order / animation_or_none / evidence
blend_plan[]: target / technique(shadow|slight_blur|scale_keyframe|
              perspective|color_match|none) / strength / why_not_more
```

- `layer_stack` 顺序固定：原片在下、文字在中、抠像主体在上。不得把文字放到最上层再声称已实现字在人后，也不得删除底层原片只留抠像层导致背景消失。
- 在写 `matte_plan` 前，必须用本轮实际暴露的抠像、蒙版或等价能力发现真实方法与资源；按主体类型和背景复杂度描述意图，再从真实返回结果中选择。没有可用方法时记录 `matte_unavailable`，不能臆造已抠像。
- 抠像质量优先于遮挡数量：默认只做 1 处主遮挡，素材较长且有多次穿越时最多 2 处且相互间隔充分。发丝、手持物、快速运动模糊处允许缩短窗口或放弃该窗口，不要靠反复修补硬保。
- `text_plan` 只写一条核心信息（片头标题、地点、主题词或一句主张），短行、单一克制字体体系、高对比。没有可靠依据时不写人名、地点、数据或不存在的事实；避开既有文字与字幕，保留左右至少 5%、上下至少 6% 安全边距。
- 文字尺寸要能被主体自然遮住：过小则遮挡看不出来，过大则整屏被压且主体读不清。文字高度应与主体高度形成明显重叠区，横向落在主体行进路径上但不压面部。
- 默认不加复杂文字动画；确有需要时只保留一个轻量入场，且不得与 `cross` 的遮挡节奏抢注意力，也不得让文字在可读期内还在运动。
- `blend_plan` 只用于让文字“坐进场景”：轻阴影、极轻模糊、与场景色调匹配，镜头有推拉摇移时用 `update_keyframes` 或等价能力做同向轻微跟随。任一手段让文字发灰、糊掉、抖动或被背景吃掉时，降低强度或删除；无关键帧能力则改选静止镜头片段。
- 阶段 5 先发现实际能力：分层与排序使用真实存在的片段复制、轨道创建与排序能力；抠像使用发现到的抠像/蒙版能力；文字使用 `add_text`、`update_text_style` 或等价能力；关键帧、动画、速度仅使用 `update_keyframes`、`retrieval_animation`、`update_segment_curve_speed` 或等价的真实能力。只调用 `capability_map` 中存在且 schema 与计划匹配的能力。
- 先完成基线画面校正（曝光、白平衡、对比、主体与背景分离度），确保主体轮廓清楚。然后按窗口执行抠像、文字与融合；一次调用后必须回读最新 draft，确认轨道序号、抠像是否真实存在、文字层位、时间范围和可读性真实成立，才能处理下一个窗口。回读未发现抠像或正确层序即视为该窗口失败，不得把蒙版、文字动画或图层顺序误报成抠像成功。

## 成片验收与边界

- 逐项核验：上下两层同素材且帧对齐、底层原片完整、抠像仅作用于顶层、层序为 背景 < 文字 < 主体、遮挡在计划时间窗内真实发生且覆盖比例在计划范围、文字有完整可读窗口、主体边缘无明显 halo/缺肢/闪烁、文字无被裁切或黑边、安全边距达标、文字退出方式明确。
- 发现问题时只对对应窗口做一次定向动作：调整文字位置/尺寸/时长、修抠像边缘或缩短抠像窗口、重排轨道、降低融合强度，或改用与主体不交叠的干净布局；计划要求的抠像未落地时仅重试同一链路一次。不得为了“补救”往其它片段追加效果；完成验收后立即推进对应客户端 checkpoint。
- 遮挡效果由主体清晰度、运动路径和文案共同触发；主体或边缘不成立时，干净的常规文字优于勉强的假抠像。用户后续明确指定某一类包装能力时，路由到原子包装 Skill 做精确替换或增强。
